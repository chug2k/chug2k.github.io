“I'm reading morning.txt first.” That was the model’s first reply when I asked it to add the numbers in two files. At that moment, both files were still unopened. The interesting part was the other thing that came back in the same reply, a request to run `read_file("morning.txt")`.

I made a lesson where you get to be the program on the other side of that request. You make four decisions and watch what happens to the files. [Try the interactive Agents 101 lesson.](/agents-101/)

# Who opens the file?

`morning.txt` holds `2`. `afternoon.txt` holds `3`. The job is to add them and write the answer to `total.txt`. Here’s the part of the Python program that does the coordinating.

```python
messages = [user(request)]
tools = [read_file, write_file]
for turn in range(8):
    reply = ask_model(messages, tools)
    messages.append(reply)
    if not reply.tool_calls:
        print(reply.text)
        break
    for call in reply.tool_calls:
        result = run_tool(call, tools)
        messages.append(tool_result(call, result))
```

1. **Ask.** Send the task and descriptions of the two tools. Now the model can ask Python to read a file or write the sum.
2. **Inspect.** Look at `reply.tool_calls`. A reply can contain a perfectly good sentence and a request for work. If you stop at “I'm reading morning.txt first,” you’ve quit before opening it.
3. **Run.** Call the reader with `morning.txt`. The filename tells Python where to look. The return value is the contents, `2` followed by a newline.
4. **Return.** Put that value into the conversation as a tool result, paired with the ID of the request that asked for it. Printing `2` would let *you* see it. Appending the tool result lets the *model* use it on its next turn.

Go around again. A reply with zero tool calls is the signal to print the answer and stop. Eight turns is the upper limit I set for this example.

# Same code, different ending

I recorded two runs on November 16. In the first, the model requested two reads and a write. On its fourth turn it had the writer’s receipt and gave its final answer. `total.txt` held exactly two bytes, the digit `5` and a newline.

For the second run I asked only for the number in `morning.txt`. The same loop took two model turns and one read. The model answered `2`, both inputs kept their original contents, and the program finished without creating an output file.
